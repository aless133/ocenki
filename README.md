# Оценки

Локальное приложение: Node.js и Puppeteer запускаются на компьютере родителя.
HTTP-маршруты обслуживает Express. Маршруты ребёнка находятся в `routes/children.js`:
Router подключён к `/:childId` и выполняет общую проверку существования ребёнка.

## Запуск

Скопируйте `.env.example` в `.env` в корне проекта. В нём задаётся порт:

```dotenv
PORT=3000
```

```sh
npm start
```

После запуска Puppeteer автоматически откроет главную страницу в видимом Chrome.
Окно запускается развёрнутым, а viewport подстраивается под доступный размер окна.
Адрес: http://127.0.0.1:3000 (или порт из `.env`). Сервер доступен только на этом компьютере.
После изменения порта перезапустите сервер.
Если браузер для Puppeteer ещё не скачан, выполните `npx puppeteer browsers install`.

При первом запуске появится папка `private/children/`.
Для каждого ребёнка скопируйте `child.env.example` в эту папку под отдельным именем,
например `masha.env` и `petya.env`, и заполните реальные значения.
После изменения файлов обновите страницу — перезапуск сервера не нужен.

- Имя файла без `.env` — постоянный ключ ребёнка (`id`). Используйте латинские буквы, цифры, дефис и подчёркивание.
- `ALIAS` — имя в списке на главной странице.
- `PROVIDER` — идентификатор обработчика сайта. Для diary.e-schools.by используйте `e-schools`.
- `SERVER` — адрес сайта с оценками.
- `LOGIN`, `PASSWORD` — данные для входа.

Значения заключайте в кавычки, особенно пароли с `#` или пробелами.
Каждый файл читается через `dotenv.parse()` отдельно: переменные разных детей не перезаписывают друг друга.

Папка `private/` исключена из Git и не раздаётся по HTTP.
Файлы `.env` хранят пароли открытым текстом.
API `/api/children` возвращает только `id` и `alias`.

На главной странице дети отображаются ссылками: например, `masha.env` соответствует странице `/masha`.
Страницу ребёнка можно открывать напрямую и обновлять. Ссылка «Все дети» возвращает на главную.

Оформление использует CSS Bootstrap из npm-пакета. Сервер отдаёт его локально по адресу
`/assets/bootstrap.min.css`; CDN и JavaScript Bootstrap не используются.

При открытии ребёнка локальная страница показывает «Ждите» с индикатором, а Puppeteer
открывает сайт провайдера в отдельной вкладке того же браузера. Вкладка остаётся открытой
после завершения или ошибки. Повторное открытие страницы ребёнка использует ту же сессию.
Для каждого ребёнка создаётся отдельный контекст браузера, чтобы учётные записи не смешивались.

Для `PROVIDER="e-schools"` и `SERVER="https://diary.e-schools.by"` реализован ученический путь:
видимая ссылка «Обучающийся» → сервер `oauth.rios.unibel.by` → видимые поля
«Имя пользователя» и «Пароль» → кнопка «Вход». Родительский вход не используется.
Обработчик нажимает элементы и печатает через Puppeteer, не отправляет формы напрямую
и не заполняет скрытые поля. «Запомнить меня» не включается.

При неверных данных локальная страница показывает ошибку. Исправьте файл ребёнка и нажмите
«Повторить вход»: данные перечитываются, используется та же вкладка. Автоматических
повторных попыток с неверным паролем нет. Реквизиты входа остаются на стороне Node.js.

После входа обработчик открывает дневник и кнопками листает недели назад до первой
доступной недели учебного года, затем собирает их по порядку до текущей недели.
Он ждёт загрузки строк таблицы после каждого клика. Даты после сегодняшнего дня
(по московскому времени) исключаются; будущие недели не открываются.

В сводке для каждого предмета показаны все отметки в хронологическом порядке,
сумма, число числовых оценок, средняя оценка и число пропущенных уроков.
«Н» и «н» считаются пропусками и не входят в сумму, количество оценок или средний балл.
При отсутствии числовых оценок средний балл отображается как «—».
Несколько оценок за урок учитываются отдельно. Наведите курсор на отметку, чтобы увидеть дату и номер урока.
Другие обозначения сохраняются в списке и сопровождаются пояснением, но не входят в расчёт.

Последний полный отчёт сохраняется в `private/reports/<childId>.json` и доступен локально
через `GET /<childId>/report`. Сама папка по HTTP не раздаётся и исключена из Git.
При обновлении страницы сохранённый отчёт виден сразу; кнопка «Обновить данные»
запускает новый сбор в той же вкладке. Если сбор прервался, предыдущий отчёт сохраняется.
Настройка четвертей и нижней границы периода в интерфейсе пока не добавлена.

Проверки: `npm test` (отдельный тестовый Chrome, вымышленные данные).
